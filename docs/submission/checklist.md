# Course submission checklist

Source: **Week 4 Project Instructions.docx**. This checklist prepares the team's later submission; creating the scaffold does not submit work, publish recordings, create a repository or grant instructor access.

The release and evidence ZIP is due **Friday Week 12 at 23:59**, and the final sprint must end by that day. Confirm calendar dates with the course schedule. Other milestones are the Week 7 process consultation, Week 13 interactive Q&A, and peer review due Friday Week 14 at 23:59.

Organize the final ZIP into numbered folders 1–7:

| Folder | Required material                                                        | Preparation                                                                                                                                                       |
| ------ | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1      | Full final product backlog, including completed and pending user stories | Export the backlog and story details from the actual tracking tool.                                                                                               |
| 2      | C4 system design documents                                               | Update diagrams to match the final implementation and explain significant decisions.                                                                              |
| 3      | Test cases covering all core features and traceable test evidence        | Complete requirement/story/acceptance-criterion links and include meaningful unit/integration/end-to-end evidence.                                                |
| 4      | Scrum evidence from every sprint                                         | Include plans, estimates, boards, burndowns, reviews and retrospectives. Add final-sprint planning/review/retro/one-standup recording links; exclude video files. |
| 5      | Self-contained PDF slide deck                                            | Use the prescribed template released in eLearn by Week 11.                                                                                                        |
| 6      | Working software release                                                 | Include all working code, clear run instructions, relevant test classes and the CI scripts used.                                                                  |
| 7      | Repository README and access information                                 | Add the actual Git repository link and ensure both instructors have access.                                                                                       |

Before packaging:

- [ ] Confirm all 20 core features work as coherent workflows; resolve or disclose remaining gaps.
- [ ] Reproduce setup and checks from the release README in a clean environment.
- [ ] Record the release commit and actual test results; review traceability and coverage gaps.
- [ ] Replace template prompts with real evidence and export live-tool records.
- [ ] Verify recording and repository access for the intended instructors.
- [ ] Include required source and configuration examples without secrets, dependencies, local databases or generated build caches.
- [ ] Submit the ZIP through the correct section's eLearn assignment before the deadline; only the latest submission is graded.

For Week 13, each team member should be able to explain the relevant code and decisions, demonstrate selected behavior, trace a requirement to tests, and discuss changes made after feedback. The course evaluates Scrum evidence and accountability as well as working software.
