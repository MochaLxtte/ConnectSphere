## How to read a result

An **Automated Pass** identifies the test assertion(s), a run before the cutoff and its tested environment. Where the log reports a complete file rather than individual names, the frozen test source, inclusion in that run and absence of skipped cases must establish that the assertion ran. **Partial coverage** identifies what the tests exercised and what part of the specification still lacks evidence. **No complete match** identifies cases without a matching execution in the material inspected, including superseded designs where applicable. The audit adds case mappings to historical runs. It ran no new tests.

Related automated checks may be useful even when a case calls for live sign-in, a persisted change or a different failure scenario. The functional R24 result and the 21 manual follow-up outcomes rely on the team’s report. The original automated classification is retained in the filterable list. The R24 result is separate from the formal release decision. [Release decision](../submission/release-record.md#release-decision)
