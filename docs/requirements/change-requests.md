## Per-change record

Copy this block for each CR and fill every line. Use **Not applicable** rather than deleting a line.

### CR-n — Title

1. **Change description:** what is requested, why, and whether it is a new requirement, a clarification or a correction.
2. **Product backlog:** new story KAN-.. (new requirement) / updated story KAN-.. (clarification) / reprioritised items.
3. **Acceptance criteria:** new or updated ACs; existing ACs still valid? original ACs re-verified?
4. **Story points:** estimate for new stories; re-estimate existing items only if understanding materially changed (log in the sprint's estimation-and-capacity.md).
5. **Design documentation:** C4 (C1–C3), class diagram, sequence diagram, data model, API contract: which were updated.
6. **Test cases:** unit, functional (TC-xx), integration, E2E and regression cases added or updated.
7. **Release burndown:** scope added (SP) recorded in `../scrum/release-burndown.md`.
